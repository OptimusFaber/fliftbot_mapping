# DePHAN M360: карта и потолочные метки (запись 2026-09-08)

Запись:

`ros-data/recordings/real/20260908/160617_dephan_m360_room`

Последние результаты:

`ros-data/results/real/20260910/160617_dephan_m360_room`

## 1. Почему карта с `(0, 0, 0)` была лучше

Это было не потому, что LiDAR физически находился в начале координат. Нулевая
экструзика была совместима с тем, как старый standalone runner трактовал
tracking frame и encoder odometry, поэтому она случайно компенсировала ошибки
старого frame-контракта.

Одометрия интегрируется из `enc_v`, `enc_dgr`, `enc_t` как траектория оси
вращения робота:

```text
v_x = v * cos(steering)
w_z = v * sin(steering) / wheelbase
```

В старом режиме эта поза подавалась в Cartographer с нулевым началом, а точки
сканов оставались в sensor-local координатах. Поэтому Cartographer фактически
подгонял траекторию «эффективного LiDAR», хотя физическая ось и LiDAR не были
разделены явно. Контрольный запуск с нулевой экструзикой побайтно воспроизвёл
старый эталонный `map.pgm`.

При первой попытке использовать настоящий mount были две ошибки:

1. В `runner.cc` origin луча переносился на высоту LiDAR, но endpoint луча
   оставался на `z=0`. Горизонтальные лучи становились наклонными.
2. После исправления endpoint стандартный фильтр `max_z=2.0` отбрасывал
   точки LiDAR, находящегося на `z=2.03 м`.

Кроме того, первая реализация смешивала позу оси и позу сенсора. Теперь
используется явный контракт:

```text
T_world_lidar = T_world_rotation_axis * T_rotation_axis_lidar
```

Для sensor-local NPZ одометрическая поза сначала переводится в LiDAR tracking
frame, а исходные лучи и origin остаются локальными координатами LiDAR. Для
уже преобразованных body/axis облаков применяется обратный режим, чтобы не
учесть extrinsic дважды.

Дополнительно был исправлен deadband скорости: `0.08 -> 0.008 м/с`. Старый
порог выбрасывал 252 encoder samples и около 1.97 м реального движения.

После этих исправлений физически корректный прогон имеет практически ту же
геометрию, что и эталон: длина траектории около `34.29 м` против `34.10 м`,
а не ошибочные `46.08 м`.

## 2. Почему метки сначала стали хуже

Метки строятся не из потолочной карты напрямую. Для каждого кадра камера
проецирует пиксель в луч, луч трансформируется в карту по интерполированной
Cartographer-позе и пересекает плоскость потолка.

Для траектории в LiDAR frame нужно использовать camera-from-LiDAR offset:

```text
camera_offset_from_lidar = camera_offset_from_axis - lidar_offset_from_axis
```

Сначала была изменена только позиция камеры/LiDAR, но остались старые углы
оптической установки камеры, которые были согласованы с прежним условным
LiDAR mount `(1.015, 0.0)`. В результате повторные наблюдения одной метки
расходились: было 2609 согласованных наблюдений вместо 3850 в V5.

Проблема была не в высоте потолка как таковой. Высота потолка участвует только
в пересечении луча с плоскостью меток и не влияет на Cartographer SLAM.

Углы камеры были перекалиброваны по внутренней сходимости повторных
наблюдений, без использования GT при построении:

```text
roll  = -0.14 рад
pitch =  0.01 рад
yaw   = -1.57 рад
```

После этого получилось 4268 согласованных наблюдений и 47 принятых меток.

## 3. Размеры и параметры последнего DePHAN-прогона

### Физические размеры

Все исходные значения заданы относительно оси вращения и измерены в
сантиметрах.

| Объект | Исходные см | ROS/рабочие м |
|---|---:|---:|
| LiDAR X | `129.0` | `+1.29` |
| LiDAR Y | `+32.0` (измерительная ось) | `-0.32` |
| LiDAR Z | `203.0` | `+2.03` |
| Камера X | `112.5` | `+1.125` |
| Камера Y | `-28.0` (измерительная ось) | `+0.28` |
| Камера Z | `127.0` | `+1.27` |
| Потолок | — | `3.13` м |

Таким образом, для траектории LiDAR:

```text
camera_from_lidar_xy = (1.125, 0.28) - (1.29, -0.32)
                      = (-0.165, +0.60) м
```

### Mapping/Cartographer

- `points_frame = sensor` для исходных DePHAN NPZ;
- `tracking_frame = lidar` (выбирается автоматически для sensor-local NPZ);
- `wheelbase = 1.410 м`;
- `max_range = 30 м`;
- фильтр высоты: `min_z = -0.5 м`, `max_z = 2.5 м`;
- encoder deadband: `0.008 м/с`;
- offline Cartographer использует online correlative scan matching;
- odometry weights в offline Lua: translation/rotation `5.0`.

### Перенос меток

- источник камеры: `recordings/.../camera_position.txt`;
- camera Y sign: `-1` (отражение измерительной оси в ROS выполняется один раз);
- `ceiling_z = 3.13 м`;
- `trajectory_pose_frame = lidar`;
- `camera_roll = -0.14 рад`;
- `camera_pitch = 0.01 рад`;
- `camera_yaw = -1.57 рад`;
- `time_offset = -0.0880254971 с`;
- V5 selection: `min_observations=12`, `component_radius=0.25 м`,
  `inlier_radius=0.12 м`, `physical_merge_radius=0.30 м`.

Основные исправления находятся в
`standalone_cartographer/runner.cc` и
`scripts/evaluation/ceiling_marker_localization_v5.py`.
